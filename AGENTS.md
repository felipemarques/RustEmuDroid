# Working on RustEmuDroid

Start with the [current handoff](AI-MEMORY.md#handoff) for verified results, open issues and the next test. Read [RULES.md](RULES.md) before operating a VM. On the original test PC, `.rustemudroid/LOCAL-HANDOFF.md` points to the private traces, disk copies and reproduction commands.

When a test, fix or release changes what the next contributor should do, update the handoff with the version, setup, measured outcome and an evidence link. Record inconclusive runs and settings restored after a test. Keep original machine-specific evidence indexed in the local handoff.

| Area | Start here |
|---|---|
| CLI and VM lifecycle | `src/main.rs` and `src/android.rs` |
| Desktop launcher, settings and translations | `src/ui.rs` and `src/ui/` |
| Guest display, keyboard, gamepads and Android actions | `src/display.rs`, `src/display/`, `src/controls.rs` and `src/toolbar.rs` |
| Android Home and its embedded APK | `android/home/` |
| BlueStacks integration | `src/bluestacks.rs` |
| Build matrix and releases | `.github/workflows/build.yml` and `docs/releases.md` |

Use `cargo fmt --all -- --check`, `cargo test --locked --features ui` and `cargo build --locked --release --features ui`. The CLI can also be built without the `ui` feature. Windows-specific integrations need a Linux build check. Real VM tests require an installed runtime and an idle profile.

For the manuals, keep `README.md` (English), `README.pt-BR.md` and `README.es-ES.md` together. Capture the actual client and Android Home in the language of each manual. The Windows integration test accepts `RUSTEMUDROID_TEST_STATE`, `RUSTEMUDROID_TEST_LOCALE` and `RUSTEMUDROID_TEST_CAPTURES`. Run the three locales sequentially against a test profile.

To verify edge scrolling on a running, idle test AVD, return to RustEmuDroid Home and run `cargo test --locked --features ui edge_scroll_reaches_selected_android -- --ignored --nocapture`. Set `RUSTEMUDROID_TEST_ADB` to the SDK's `adb` executable, `RUSTEMUDROID_TEST_CONSOLE` and `RUSTEMUDROID_TEST_TOUCH_RPC` to the session's console and gRPC ports, and `RUSTEMUDROID_TEST_AVD` to the path reported by `adb -s emulator-<console-port> emu avd path`. Set `RUSTEMUDROID_TEST_TOUCH_DEVICE` to the primary virtual touchscreen node identified by the selected guest's `getevent -lp` output. The test uses a temporary control scheme on Android's Device Info page and returns to Home.

Use the same selected AVD, environment and idle Home state for `moba_scroll_and_free_look_reach_selected_android`. This opt-in test checks the touchscreen events generated by movement relative to the hero, anchored scrolling and free look.
