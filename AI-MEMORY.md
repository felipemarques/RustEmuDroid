# Engineering memory

| Decision | Consequence for future work |
|---|---|
| The Rust desktop client uses eframe/egui and Glow. Android Home is a native Android activity inside the guest. | Games, apps and Home navigation share one Android session. Host controls and preferences belong to the desktop window. |
| The native runtime uses the Android Emulator controller and ADB. The Windows Kemu engine can provide its matching Android image and graphics stack. | A different hypervisor or disk format alone does not supply the controller, guest drivers or display/input protocol the embedded UI uses. |
| Each Android profile owns its writable storage. | Check the profile before attributing missing games, different Android versions or different GPU settings to a regression. |
| Home is bundled in the executable as a signed APK. | Rebuild the APK when changing Home sources or resources. Preserve the signing key when upgrading a profile in place. |
| New desktop installations default to pt-BR. The client also supports en-US and es-ES. | Store the selected locale with the launcher preferences and apply it to the bundled Home; third-party apps manage their own language. |
| The sidebar keyboard opens the quick controls menu. The editor floats over the fitted guest image. | Anchor markers to normalized Android coordinates. Cover the game with an egui foreground area when editing so a panel or letterbox never becomes a touch target. Existing schemes remain in the AVD's `touch-maps.json`. |

## Verification history

- Game measurements on the integrated Radeon 780M include each emulator, game presets, individual runs and adapter verification. [Benchmark and measurements](benchmarks/stk-1.5/radeon-780m/README.md)
- On the RTX 5070 Ti, both RustEmuDroid and BlueStacks presented about 60 frames per second during short BombSquad stress-test samples. The PUBG Showroom stayed near 29 on RustEmuDroid after a 900p/720p/900p resolution change. In a separate inventory trace, PUBG's game thread ran for 1.32 s during a 2.17 s gap in its own buffer stream. A desktop frame-copy A/B produced no repeatable improvement. War Thunder Mobile did not reach gameplay. [Game test conditions and results](docs/game-testing.md)
- Refer to the [Windows and Linux workflow](.github/workflows/build.yml) for the current toolchain and artifacts. Native UI captures use the [Windows window test](src/ui/live_window_test.rs) with an actual Android guest.
- BlueStacks 5 on Windows opened SuperTuxKart in Pie64. Independent QEMU reached the original Linux 4.19.195 kernel and entered its initramfs. Android userspace, graphics and games on the copied image remain unverified. [Device list and boot experiments](docs/bluestacks-lab.md)
- The Windows diagnostic attaches the copied disks through disposable overlays. With VirtIO block devices, the original initramfs reaches input module initialization and panics in the BlueStacks message driver. With legacy storage, the serial watchdog reports a stuck SCSI error handler at roughly 29 seconds. [Repeat the diagnostic](docs/bluestacks-lab.md)
- The opt-in system-mount diagnostic builds a temporary, verified, read-only SquashFS from the copied Pie64 root. Independent QEMU attached the original Android system directory. The vendor configuration reported an empty `android_id` and Android boot completion remains unverified. [System-mount diagnostic](docs/bluestacks-lab.md#opt-in-system-mount)
- In the Android 17 Google Play profile, the package manager retained the version of Home after rejecting an incomplete APK during an earlier shutdown. Check the installed package path before trusting the version, reinstall in place when necessary, and flush guest writes before shutting down.
- The Windows live run verified both Home boots in each locale, the editor in SuperTuxKart and capture of PNG, H.264 MP4, animated JPEG XL and GIF. JPEG XL and GIF decoded to 30 frames at 10 FPS. The opt-in Android input test observed swipe and simultaneous opposing pinch contacts through the virtual touchscreen. [Live input test](src/display/live_input_test.rs)
- With the Google Play AVD selected, the controls editor test mapped an individual D-pad direction, held it with a second binding, and observed two Android tracking IDs and both releases after focus loss. A separate regression checks ordered same-frame taps through the desktop input pipeline. [Editor and live Android check](src/display.rs) · [D-pad regression](src/display/mapping.rs)
- Edge scrolling produced the expected bounded drags on the Android 17 touchscreen. Tilt uses the emulator's physical rotation model. A +15° X binding shifted a live baseline of −4.75° to +10.25° and restored it on release. [Android input tests](src/display/live_input_test.rs) · [Rotation and restore tests](src/display/tilt.rs)
- The Windows launcher and the native test harness share one window factory. Set both Win32 icon sizes from group resource 1. The real-window regression test checks the handles Windows returns for the caption and taskbar.
- The animated mascot uses the original logo. Guest Home v3 animates only a visible, focused empty state. The desktop animates boot, shutdown and About. The window and taskbar icons use the static brand resource. Android 17 offscreen rendering verified portrait, landscape, compact height and both directions of the step while a different app stayed in the foreground.
- Android 17 touchscreen events verified hero-relative MOBA movement and both release paths, opposite anchored wheel swipes, and free look from keyboard and mouse. The wheel option under Rotate uses a single contact and preserves two-contact rotation for older schemes. [Input tests](src/display/live_input_test.rs) ? [Steering regression](src/display/mapping/gestures.rs)
- A 48-second PUBG Inventory route with four opens and closes produced 25.04, 25.06 and 24.67 guest presentations/s at Balanced, Smooth and Balanced Lobby graphics. All three had long pauses. [Inventory settings test](docs/game-testing.md#does-the-lobby-smooth-preset-help-with-inventory)
