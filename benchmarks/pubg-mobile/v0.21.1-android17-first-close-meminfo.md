# PUBG MOBILE 4.7.0 first Inventory close with Android memory categories

The official RustEmuDroid 0.21.1 ran the existing Google Play Android 17 profile on the RTX 5070 Ti at 1600 x 900 and nominal 60 Hz. The route kept the original Global Balanced Lobby settings. A PUBG update documented a toggle for Ray in the Lobby. The inspected scene showed no active Ray to hide, so the experiment kept the scene intact and measured memory around the first Inventory close. [Publisher update notes](https://www.pubgmobile.com/webplat/info/news_version3/35372/60662/60663/60724/60725/60726/m22521/202209/922032.shtml)

Each lap used a fresh game process in one guest boot and checked the unobstructed Lobby, Inventory Outfits, and the same Lobby after the first close. All laps recorded Android SurfaceFlinger and ordinary Linux process counters. The two instrumented laps also took process-specific dumpsys meminfo -d snapshots in Inventory and after Lobby returned. Matched waits kept those calls outside the selected pause. [Sanitized measurements and relative timestamps](v0.21.1-android17-first-close-meminfo.json)

Presentation gaps were 1649.81 ms in the available controls and 1610.32-1631.55 ms with detailed snapshots. This bounds the intrusion check to the observed runs.

Android's Unknown category accounted for the largest sampled RSS increase in both detailed runs. The coarse classification leaves their underlying allocations unresolved.

Fault totals cover complete 100 ms sample intervals within the selected ready gap, or its presentation gap when a ready endpoint is ambiguous. The JSON includes time coverage, sampled RSS ranges and the detailed snapshots' distance from the tap.

Process categories describe residency across the Inventory and Lobby states. Minor faults count events, including pages that can be reused or released between snapshots. Locating the faulting allocations requires address-level evidence beyond these snapshots. Fresh processes still use the installed game's ordinary caches.
