# RustEmuDroid v0.16.0

Choose **Settings → Graphics → Android refresh rate** to request a display rate for the next boot. The Windows selector reads the current mode of the monitor containing the launcher and offers rates up to that value when Windows reports it. The CLI accepts the same request through `boot --refresh-rate 90`. Existing preferences use the profile's original rate.

On supported Android 15 and later images, choosing more than 60 Hz also requests the matching minimum refresh rate and temporarily disables Android's default frame limit for games. Each game can still enforce its own limit. Select **Use profile refresh rate** to use the original display timing. In the SuperTuxKart 1.5 Black Forest replay on the RTX 5070 Ti, setting only the virtual display to 90 Hz left the Android 17 game at 45 FPS. Selecting 90 Hz in the v0.16.0 client applied both Android preferences and the game reported **83.98 FPS** over the replay. Android presented **81.96 frames/s** during the sampled race segment, and the Rust panel processed **78.82 frames/s** in nearby timed intervals. The warmed 60 Hz reference reported **59.95 game FPS**. [Measurements and configuration](../game-testing.md#managed-windows-runtime-and-android-refresh-rate)
