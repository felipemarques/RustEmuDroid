# RustEmuDroid v0.13.4

On a fresh Windows or Linux setup, `doctor`, `init` and `boot` now show the command to review the built-in Android runtime download when automatic discovery finds no installation. Run the command from the extracted release folder. Reviewing the download shows the package size and terms. An explicitly selected runtime that is missing a tool still reports that tool's path.

The English, Brazilian Portuguese and Spanish guides also include the tested startup settings for PUBG MOBILE on Kemu Android 16. [Android 16 startup results](https://github.com/felipemarques/RustEmuDroid/blob/v0.13.4/docs/game-testing.md#pubg-startup-on-kemu-android-16)

## Windows managed runtime verification

On the Windows 11 test PC, the official v0.13.4 executable installed Google's Android Emulator 37.3.10, Platform Tools 37.0.3 and Android 17 Google Play x86-64 revision 7. The test imported existing license records. The desktop process had a fresh local app data directory, an empty conventional SDK location and only Windows system directories on its executable search path. The host also had a separate SDK installation for other development work.

The packaged window started QEMU and an ADB server from the managed runtime. It reported `sys.boot_completed=1` in 80.7 seconds on that fresh profile. At 91.3 seconds the verifier found the bundled Home activity in the foreground and verified that Play Services and the Play Store were installed. Closing the window returned exit code zero and left no emulator process. These are first-boot observations on one machine.
