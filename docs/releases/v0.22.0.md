# RustEmuDroid v0.22.0

Windows x64 users can select a prepared Vulkan cache engine for an existing Android profile. In **Settings → Runtime, image, and profile → Vulkan memory cache (experimental)**, choose the folder containing `staging.json` or its `sdk` subfolder. Save to restart Android with that engine. Installed games, accounts and saves stay on the profile's existing Android disk. **Use default engine** switches that profile back. [Windows settings](../../README.md#choose-a-profile) · [Prepare an engine](../../experiments/whpx-clock/README.md)

The same option is available from PowerShell. Supply the data directory of an initialized profile and replace the engine path with the folder prepared on your computer. If you normally pass `--sdk`, keep it pointing to the runtime that contains your Android image.

```powershell
.\rustemudroid.exe --state-dir 'D:\Android\MyProfile' boot --gpu host --vulkan-cache-runtime 'D:\Android\CacheEngine'
```

The desktop verifies the staged modules, starts the renderer with Vulkan caching enabled and reports its confirmation in the startup output. The Windows download contains the desktop client. The experimental engine is prepared separately.

On the Windows test PC, the v0.22.0 CLI booted an existing Android 17 Google Play profile in **24.5 seconds** with the separately staged engine. The live Qt QEMU was the cache build, gfxstream selected the RTX 5070 Ti and Android reported `sys.boot_completed=1`. The process exited cleanly after `--check`. The run used a single VM, a separate stock SDK for the Android image and the prepared engine built from 12 project-linked binaries.

In four SuperTuxKart 1.5 Black Forest replays with the v0.21.1 window, Android 17, an RTX 5070 Ti and a 90 Hz target, the same experimental engine went from **85.56 to 90.19 game FPS** with caching. Android's P99 frame interval fell from **22.92–23.10 ms to 14.53–14.63 ms**. The figures apply to this game, GPU and profile.
